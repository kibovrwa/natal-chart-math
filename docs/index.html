Compute a natal chart in JavaScript

A natal chart here is a civil clock time and a geographic place, turned into ecliptic longitudes. The Sun, the Moon, and the planets are geocentric positions on the ecliptic of date. The ascendant is the longitude on the eastern horizon. The midheaven is the longitude on the local meridian. House cusps are a convention laid on those angles.

The longitudes and the horizon geometry are ordinary astronomy. What someone then says about character or fate is a different kind of writing. One reader-facing walkthrough is how to read a birth chart.

This site is the reference math for that astronomy, written against astronomy-engine 2.1. The only dependency of the repository is that library. Node 18 or newer runs the scripts in examples/. The free chart at astralhoro.com/chart is built on the same approach, and how it works tells that story for readers who are here for the result rather than the JavaScript.

What you pass in

Four inputs fix the chart.

  • A civil date, such as 1994-04-12.
  • A clock time, such as 07:42.
  • The birthplace’s IANA time zone, such as Asia/Singapore. The zone of the machine running the script is a different place and selects a different instant.
  • Latitude φ, north-positive, and longitude λ, east-positive, in degrees.

The worked example on every page is 12 April 1994, 07:42, Singapore. The zone is Asia/Singapore, the latitude is 1.3521°N, and the longitude is 103.8198°E. Singapore does not use daylight saving, and the civil offset that morning is eight hours ahead of UTC, so the instant is 1994-04-11 23:42 UTC.

Civil time to UTC

Treat the typed year, month, day, hour, and minute as a UTC timestamp. Format that instant in the target zone, and add the difference between the typed numbers and the numbers the zone displays. Repeat until they match. A real local time settles within a few passes, because each pass removes the error in the offset. Stop after four.

function zonedToUtc(date, time, timeZone) {
  const [y, mo, d] = date.split("-").map(Number);
  const [hh, mm] = time.split(":").map(Number);
  if (![y, mo, d, hh, mm].every(Number.isFinite)) {
    throw new Error("Expected a date YYYY-MM-DD and a time HH:MM.");
  }
  const wall = Date.UTC(y, mo - 1, d, hh, mm, 0);
  let utc = wall;
  const fmt = new Intl.DateTimeFormat("en-US", {
    timeZone,
    hourCycle: "h23",
    year: "numeric",
    month: "2-digit",
    day: "2-digit",
    hour: "2-digit",
    minute: "2-digit",
  });
  for (let i = 0; i < 4; i++) {
    const part = Object.fromEntries(
      fmt.formatToParts(new Date(utc)).map((p) => [p.type, p.value])
    );
    const shown = Date.UTC(
      +part.year, +part.month - 1, +part.day, +part.hour % 24, +part.minute
    );
    if (shown === wall) return new Date(utc);
    utc += wall - shown;
  }
  return new Date(utc);
}

hourCycle: "h23" asks for hours 00–23. The parsed hour is still taken modulo 24, because some engines format midnight as 24.

Intl applies the historical daylight-saving rule for the civil date you pass. The same clock numbers in America/New_York are a different UTC instant, and the April offset there differs from the January offset. When clocks fall back, one civil time happens twice. When they spring forward, one civil time happens never. Run the conversion on a clock time that exists in that zone. A skipped hour has no UTC instant whose zone clock shows the typed numbers, and four corrections are enough for a real local time.

const when = zonedToUtc("1994-04-12", "07:42", "Asia/Singapore");
// 1994-04-11T23:42:00.000Z

Three calculations

From that UTC Date, the chart is three pieces. The next two pages carry the formulas and the code.

  1. Ecliptic longitudes of the Sun, the Moon, and the eight planets. A geocentric longitude is the same from every city. The city still chooses the time zone, and the time zone chooses the instant.
  2. The ascendant and the midheaven, from Greenwich sidereal time, the place’s latitude and longitude, and the obliquity of date.
  3. A house system laid on the ascendant. Whole-sign houses and equal houses each need only that one angle. Both stay defined at a high latitude.

examples/positions.js and examples/ascendant.js print this for the Singapore birth:

The rising sign is Taurus. The Sun is still in Aries, about 9.9° of longitude short of the ascendant. Jupiter and Pluto are the two bodies whose geocentric longitude decreases over the next day. The planet page lists all ten positions and that daily motion.

Run the scripts

From the repository root, after npm install:

node examples/positions.js
node examples/ascendant.js
node examples/houses.js

positions.js prints the ten longitudes. ascendant.js prints Greenwich apparent sidereal time, the right ascension of the meridian, the obliquity, the ascendant, and the midheaven. houses.js prints whole-sign cusps, together with Porphyry and Placidus, for Singapore and for the same instant at Tromsø.

What a clock time is worth

Tropical longitude is measured eastward from the March equinox of date. Zero is 0° tropical Aries, and each sign is the next 30°. astronomy-engine already returns that longitude. A sidereal chart subtracts an ayanamsa from these degrees. This reference keeps the tropical value.

With an unknown birth time, local noon only holds the date. The Moon’s place is uncertain by roughly 13° across that civil day, and the ascendant changes sign in about two hours on average. House cusps want a known clock time. The Sun moves about a degree a day, so the solar sign usually holds still across that uncertainty.

Wrap every longitude into [0°, 360°) before you take a sign. Compare two longitudes by the shortest arc: a raw gap of 359° is a separation of 1°.
